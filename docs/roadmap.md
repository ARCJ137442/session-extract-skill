# 迭代路线：从「能捞」到「零长脚本丝滑提取」

> **愿景**：用户拿到一个链接 / 一个 session id，**不需要写任何长脚本**，
> 就能得到目标工具可以直接吃的产物，并且**自带无损自证**。
>
> **「自带无损自证」的范围（别把话说宽）**：
> - 分享链接路径的产物（`rescued-session/v1` 与 `chatgpt-import/v1`）→ **内嵌** `verification`
> - 导出包路径的产物 → **内嵌** `verification`（按会话分组）
> - **跨源并集产物** → 不内嵌，靠**外部** `verify_merged_deepseek.py` 的 A1–A7 门禁自证
>   （并集同时含两种来源，内嵌单一自证会说不清「跟谁比」）
> - **引用精确度**同样分路径：分享链接路径**逐条精确**；导出包路径**原理上还原不出**
>   （格式不携带引用关系，产物里如实标 `unresolvable` + 候选池）；并集里约一半可精确解析。

判断标准很简单：**如果用户为了用这个 skill 还得自己写一段转换代码，
那这个 skill 就没做完。**

## 一、这一轮已完成（v1.1）

| 项 | 内容 | 为什么 |
|---|---|---|
| 共享归一模块 | `scripts/deepseek_common.py`：占位符标题识别、URL 锚点归一、派生字段剥离 | 「同物异形」的规则只定义一次，提取侧与合并侧同一把尺子 |
| 占位符标题名单化 | 标题占位符的**文案会变**（中文 / 英文都出现过），写死字符串会让 `title_is_placeholder` 静默误判 | 静默的假信号比报错更危险 |
| URL 锚点归一 | 结果条目新增 `url_normalized` / `url_anchor`；原值不动；同文档的多个摘要收进 `variants` | 同一篇文章被登记成多条、snippet 互相不补齐 |
| 只读模式自证 | `--format json` 的 `_meta.verification` 带着多重集自证结果 | 「没丢没重」要随产物一起流转，而不是靠人记得跑 `--verify` |
| stdout 跟随控制台码页 | `console_encoding()` 用 `GetConsoleOutputCP()` 取真实码页 | 钉死 UTF-8 会被 PowerShell 按 cp936 解码 → **静默乱码**；要字节级保真走 `--out`/`--outdir` |
| ChatGPT/OpenAI 形态 | `--format openai` / `to_openai.py` / `--as openai` | **本轮最关键的一项**：搬运规则沉淀在 skill 里 |
| 假 PASS 修复 | 校验跑不起来时报 `SKIPPED` + 退出码 4，**不再报 PASS** | 「没验过」≠「验过了」 |
| 回归测试 | `tests/test_deepseek_paths.py`（合成数据，stdlib unittest） | 一次惨烈的 bug 复盘只留在注释里，下一次重构就会重演 |
| 独立验收机制 | 每轮改动后派**无上下文验收 Agent**，只给仓库路径 + 验收标准 | 它抓出了我们自己的三轮盲区：真实 share_id 仍可匿名访问、cp936 下管道崩溃、导出包路径引用是**猜**的 |
| 脱敏到提交历史 | filter-branch 重写所有提交 + 清 `refs/original` + gc | 规则说「不写进提交历史」，就真的不能留在历史里 |
| 引用「精确 vs 候选」 | `sources` = 真正被引用的那几篇；`candidates` = 其余检索结果 | 「有来源」不等于「来源对」——精确与候选必须分开 |
| `--strict` 形态 | 只输出 `[{role, content}]` | 富产物**不能**直接 POST 给严格的 chat API，文档不承诺做不到的事 |
| 幂等重转 | 把转换后的产物再喂回去，消息/引用/思考链全部沿用 | 静默产出 0 条 message 是最坏的结果 |
| 平台探测 + 元信息都从「任意事件」补齐 | 首行不是消息的真实会话，sessionId / cwd / gitBranch 从**任意旁路事件**里补 | 实测 143 个真实 Claude Code 会话里 59 个（41%）首行不是消息——只修探测不修元信息，一半会话仍是全 N/A |
| `--json` 对所有路径生效 | Claude / Codex 路径也输出机器可读 JSON | 以前 `--json` 只在 `--scan` 被消费，其他路径**静默忽略**它 |
| 脱敏扫描器可当门禁用 | 固定仓库根、扫工作区未提交改动、扫到 0 个 blob 直接报错 | 「在错目录跑 → 扫到 0 个 → 报干净」是**假绿**，比没有门禁更危险 |

## 二、下一批（v1.2 候选）

### P2-1 视图分层

现在产物是**搬运工视角**：忠实、结构完备，但消费方要先理解 7 种
fragment 类型才能用。缺的是**视图层**：

| 视图 | 给谁 | 现状 |
|---|---|---|
| `transcript`（全量，含 THINK/TOOL） | 审计者 | ✅ |
| `messages`（纯对话） | 想要「聊天记录」的人 | ⚠️ 要自己过滤 |
| `chat_messages`（OpenAI 格式） | 另一个 LLM | ✅（`to_openai.py`） |
| `citations`（标记 ↔ 来源） | 做事后核查的人 | ✅ 已实现（精确来源在 `sources`，其余在 `candidates`） |

另外 `transcript` 把对话与工具调用混在一个扁平数组里，且 THINK 与
RESPONSE **role 同为 assistant**——消费方按 role 重建对话流时，
思考链会污染正式回答。

### P2-2 测试覆盖

现在只有归一与转换这一段有测试。还需要：

- 合并路径（`merge_deepseek.py`）的夹具：锚点变体、字段贫瘠 vs 富载荷
- `verify_merged_deepseek.py` 的断言夹具：每种失败模式各一个
- 一个**端到端**夹具：链接 → 产物 → 转换 → 自证

原则不变：**夹具一律合成数据**，真实数据只作为运行时输入。

### P2-3 断言体系的盲区 ✅ 已完成（A7）

已加 **A7「一篇文档一条记录」**：登记表无重复、登记表与结果列表双向对齐
（无孤儿/漏登）、单个 results 列表内无重复归一 URL、源侧每个变体都在并集
`variants` 里。A7 对**改写前**的产物判 FAIL（丢 577 个变体）——新断言有区分度。

仍可补的：
- 引用标记与来源的对应关系不得悬空（目前由转换侧保证，尚未进断言）

### P3-1 清理个人机器的化石（进行中：见下方「第六轮复查」）

- `verify_merged_deepseek.py` 写死的本机绝对路径 → 改成**三个参数全部必填**
- 报告正文里把某一次样本的**事实写死成通用结论** → 改成从数据算出来
- 报告里硬编码的样本结论 → 变成按特征识别出来的结论
- 产物 `_meta.source.file` → 只留**文件名**（绝对路径会在转手时泄露目录布局），
  sha256 保留
- 提交历史整体重写（filter-branch），把机器路径、真实分享 id、真实会话
  标题/正文、导出包指纹从**所有提交**里清掉

仍可补的：
- 远端 PR ref（`refs/pull/*`）里的旧历史也要清

### P3-2 工程化

- 类型注解（现在 7 个脚本零注解）
- `sys.path.insert(0, ...)` 的目录劫持风险 → 统一 append
- 三套 Markdown 渲染器（分享侧 / 导出侧 / 合并侧）规则不一致
  → 收敛成一套，或明确各自的适用范围

## 三、更远（v2 方向）

### 3.1 会话 ABI

`rescued-session/v1` 现在是**一份文件格式**；它可以变成**一套会话 ABI**：

```
平台 ──▶ 打捞器 ──▶ 会话 ABI ──▶ 任意消费方
                       ├─ 对话流视图（messages）
                       ├─ 事件流视图（transcript）
                       ├─ 证据链视图（citations + references）
                       └─ 搬运自证规范（lossless proof）
```

### 3.2 引用语义要迁移，不只是文字

从 DeepSeek 迁到 OpenAI，真正难的不是文本，是**引用的语义变了**：
DeepSeek 的 `[reference:N]` 指向一次具体搜索；
OpenAI 的 `annotations[]` 指向一段具体的字符区间。

这才是「把会话喂给另一个 LLM」最难的一层，也是最适合由 skill 一手承包的：
**把「这句话凭什么这么说」这根链条完整迁移过去，而不是只搬文字。**

### 3.3 离线复现

现在必须联网才能重跑分享链接路径。加一个「从已保存的原始 API JSON
离线重建产物」的入口（`--from-file`），让打捞结果**可复现、可审计、可回归**
——不必每次都去打线上接口。

## 三点五、第六轮复查的教训（比任何功能缺陷都重要）

> 这一节记的不是「改了什么」，是**改的时候踩了什么**。

1. **用门禁当掩护，比没有门禁更坏。**
   我为了不让扫描器抓到测试里的真实会话 id，把它写成 `"ab" + "cd"` ——
   验收员反混淆后发现：**那还是真实 id**，而且已经进了公共仓库。
   「让门禁看不见」正是门禁存在的理由被作废的方式。
   → 现在的规矩：**个人标识符绝不进代码**。机器名、盘符根、项目 id 一律用
   `--deny <token>` 作为**输入**传进扫描器；测试里的 id 一律 `uuid.uuid4()` 运行时生成。

2. **门禁必须能看穿「藏起来」。**
   扫描器现在会先**还原字符串拼接**再比对——因为藏法不止一种。

3. **「自排除」这种机制必须被真实路径验证。**
   旧的排除逻辑按路径判断，但已提交 blob 的标签是 **sha** → 排除从未生效；
   自带测试验的是一个**不会发生的分支**，所以它一直「通过」。
   → 现在用 `git ls-files -s` + `rev-list --all -- <自身路径>` 建 sha→路径映射，
   并有测试用**真实 blob** 验证。

4. **Windows 上「钉死 UTF-8」是把崩溃换成了静默损坏。**
   PowerShell 按控制台码页解码子进程输出 → 钉死 UTF-8 = 中文乱码且**不报错**。
   → stdout 改为**跟随控制台真实码页**；要字节级保真的产物走 `--out` / `--outdir`。

## 四、原则（迭代时不要破例）

1. **忠实优先于美化** —— 线性化/转换都只是视图，原始容器永远留着
2. **归一规则只定义一次** —— 同一事实两处实现 = 迟早漂移
3. **没验 ≠ 验过了** —— 跳过校验要如实标 SKIPPED，不能报 PASS
4. **静默丢失比报错更危险** —— 宁可多一个字段、少一个字段
5. **脱敏** —— 代码、文档、提交历史里不出现个人路径、真实会话内容、
   真实标题、真实 share_id；夹具一律合成数据
6. **搬运规则沉淀在 skill 里** —— 不在用户的临时脚本里
